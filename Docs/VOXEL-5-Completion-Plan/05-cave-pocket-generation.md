# 05 — Planned caves, noise pockets, roof and protection

**Outcome:** finite and infinite-style worlds generate the requested seeded network and optional pockets through the actual chunk pipeline. A scratch plan or attractive preview is not a completed M5. Every published route and entrance must pass [06](06-final-mesh-route-certification.md).

## Baseline and dependencies

VoxelLandM5CandidatePlanner, EntrancePlanner, RouteBuilder, integer geometry, portal handshake/closure, PocketNoise/Mapping, CarveMasks, EntranceMask, ChunkCarve, Composition and BaselineWindow exist as isolated helpers and have authored automation. PlanPreparation still returns Unproven and BoundBase does not publish a base; runtime cave generation is not connected. Their limits and tests are not acceptance evidence. The old ±1,048,576 cm M5 logical envelope does not satisfy the intended large streamed world. The working tree includes interrupted, unreviewed edits: inspect it before implementation. Earlier docs' old-world preservation rules are superseded by the owner's explicit no-legacy decision, not by permission to delete unrelated user assets.

Both world settings types share one graph. Finite worlds support bounded global height and erosion; infinite worlds require regional planned caves **and** local pockets and must reject operations needing a complete finite world. The owner approved the proposal as the implementation basis and requested configurable values: starting defaults are 8–24 chambers, two entrances, 0–3 loops, tunnel radii 250–400 cm, chamber radii 500–1000 cm, and pockets disabled. Attachment/enclosed-void policy, protection, water and capsule profile are configurable. These defaults are not a proof of clearance; numerical limits and performance targets remain engineering inputs, not measurements.

Dependencies: [01](01-world-assets-runtime.md) supplies typed immutable world snapshots and runtime lifecycle; [02](02-mode-capability-enforcement.md) supplies shared graph/provider validation; [04](04-infinite-world-streaming.md) supplies wide keys and regional ownership; [07](07-shared-resource-accounting.md) supplies shared leases and work; [06](06-final-mesh-route-certification.md) is the required final certificate.

## Ordered implementation

1. Define one current stage/program/plan contract: units, checked coordinates and rounding, seed namespaces, stable IDs, canonical graph/provider/mask inputs and format/version rejection. Include both world kinds, capsule and validation settings, pocket/roof/protection/water rules, stage order and backend in identity. Keep full descriptor, plan dependency key, plan hash and chunk hash separate; no migration readers for obsolete development identities.
2. Factor one immutable native final-sample implementation used by runtime, CPU preview, cooked reconstruction and validation. Trace actual M4 base, int16 quantization/saturation, optional Smooth Density, carving and final conversion. M4 quantizes before smoothing; a post-carve conversion has its own units/ties/saturation. Negative terrain is solid; negative cave primitive is cave air; hard subtraction is max(T, -C). Disabled/zero pocket contribution is an exact density no-op under the current format.
3. Finite planning runs only after matching global height/control/erosion data is ready. Validate the whole half-open planning region, entrance surface and all sample/filter/mesh/protection footprints before admission. Build candidates in deterministic total order, with bounded retries, configured branches/loops and explicit failure for empty or impossible requests; do not silently remove a failed edge.
4. Infinite planning is on demand. Derive each interior stream from world seed, stage identity and signed region key; derive each portal from the canonical unordered neighboring face and immutable descriptor. Both sides must agree on portal geometry, full key, feet anchors and sampled overlap. Use a bounded dependency closure and explicit boundary-publication protocol; do not recursively require the entire infinite world or publish a unilateral portal. Failure/unavailable neighbor is reported, never replaced by pockets.
5. Extend the current integer-centimetre cave helpers for wide world positions through checked region-local arithmetic and global int64 keys. Logical IDs/samples must not depend on floating origin, presentation coordinates, task order or which chunk owns a sample. Make supported vertical/voxel/backend/coordinate bounds explicit and reject overflow instead of clamping or switching algorithms.
6. Derive conservative primitive influence bounds, including saturation, quantization, smoothing, displacement and sample/mesher halos. Hard subtraction can alter negative terrain outside a primitive radius. Use exhaustive scanning until an independently verified conservative cutoff/index is available. Unknown cave or pocket bounds force NeedsSamples; never trust M4-only uniform classification for a carved field.
7. Derive network and pocket permissions separately. Compute full 3D roof/protection influence from the actual baseline field, including multiple vertical crossings and enclosed cavities, not only a height grid. Protection always wins. Permit a surface break only inside the recorded opening and only when all changed sample-to-mesh influence remains inside that opening. Keep FieldSafety as one check, not a complete roof certificate.
8. Integrate PocketNoise and PocketMapping with global signed coordinates, current versioned basis and exact threshold/amplitude mapping; extend region-local arithmetic for wide world positions without changing samples at seams. Enforce depth, roof, protection, water and attachment policies as authored; do not accept ignored toggles. Define missing water/mask data and enclosed-void behavior. Eight hashes/temporary allocations per sample are currently unmeasured; optimize only with independently checked identical output.
9. In VoxelLandWorld.cpp worker and editor preview generation, capture matching complete plan-set, masks and provider lease, apply ChunkCarve to all stored samples, hash final density and mesh it. Matching descriptor, plan/region generation, epoch, cancellation and consumer lifetime are checked immediately before publication. Generate from scratch in deterministic order and propagate cancellation, outside-domain, unavailable neighbor/provider, exhaustion and validation failures without stale fallback.
10. Submit all final chunks, entrance/region closure, route and protection data to [06](06-final-mesh-route-certification.md). A successfully planned but uncertified network cannot be cached or published. Lifecycle isolation and data-only server operation are required for both modes.

## Automation to write; human runs

- Analytic independent sign/conversion/threshold/radius cases, ties and saturation, invalid/overflow/zero settings, stable seeds and separately calculated packets; indexed queries versus exhaustive reference including outside-radius influence.
- Finite seeded main/branch/loop/entrance connectivity; impossible spacing, retry exhaustion, protection conflicts, no entrance and over-budget. Verify all feature IDs and no partial candidate/cache publication.
- Infinite shared portals and full dependency closure across positive/negative axes, region corners, absent/mismatched/reordered neighbor, different worker counts. Compare complete X/Y/Z density overlap planes and mesh boundaries including filter halo, pocket-only and combined modes.
- Roof/protection near caves, pockets, intended entrance and overhang/multiple crossings; deliberate unsafe output must fail [06](06-final-mesh-route-certification.md). Exercise water/attachment/enclosed policies, both explicit values and unavailable inputs.
- Test disabled/zero contribution, immutable input mutation/stale result, cancellation during each bounded stage, resource one-below/at/above, provider loss, origin rebasing and two-world teardown. Add regression fixtures for supported behavior, without historical identity migration claims.

## Exit criteria and decisions

- [ ] Both modes generate actual planned entrances, connected networks and separately configurable pockets through game and preview; infinite generates regions on demand with matched neighbors.
- [ ] Every route and roof/protection condition passes the final meshed, quantized certificate in [06](06-final-mesh-route-certification.md), after every enabled contribution.
- [ ] Human runs named automation, editor interior/cross-section and in-game inspection for recorded seeds; compares hashes across target hosts; runs real cook and dedicated server. Record actual commands, revisions, engine/compiler/OS/backend and skips. Physical character movement remains M11 follow-up.
- [ ] Resolve numerical scale/influence cutoff and precision, entrance/roof margins, neighbor-closure failure policy, protection/water defaults, pocket classification, resource caps and provider guarantees. Values in existing proposals are not performance measurements. Do not call M5 complete until the owner accepts the evidence or explicitly changes acceptance.
