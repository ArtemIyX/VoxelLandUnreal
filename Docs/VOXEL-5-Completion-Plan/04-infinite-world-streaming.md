# 04 — Infinite-style world streaming and regional cave ownership

## Outcome

The infinite-world asset provides Minecraft-like demand-driven terrain and caves over a large, explicitly supported signed logical domain. It supports **both** bounded regional planned networks and local noise pockets, including deterministic shared portals. “Infinite” is a product mode, not a promise of unbounded machine integers, floating precision or memory. Finite world behavior and erosion remain in 01/05; do not replace regional planned caves with unconnected pockets on failure.

Depends on [01](01-world-assets-runtime.md), [02](02-mode-capability-enforcement.md), [05](05-cave-pocket-generation.md), [06](06-final-mesh-route-certification.md), [07](07-shared-resource-accounting.md), and 03's removal of obsolete backend selection. User wants both world modes, so rejecting all regional networks or all local pockets is not an acceptable final implementation.

## Current state

`VoxelLandInfiniteCoordinates` provides checked int64 scalar split/join, negative floor division and canonical faces. It is **isolated**: current chunk keys/world scheduling/meshing still use `FIntVector` and rendering precision bounds. M5 candidate/identity code still has ±1,048,576 cm global limits and finite bounds. Regional seed, portal handshake, closure, budget, chunk overlap and route geometry helpers exist as limited building blocks; matching portal metadata is not a full world or final-field certificate. Existing region closure accepts a *bounded supplied set*, not arbitrary infinite connectivity or atomic world publication. `VoxelLandM5PlanPreparation` remains fail-closed. The in-flight LegacyFloat removal and tests are uncommitted; do not assume they compile or overwrite them.

## Work plan

1. **Specify the world coordinate contract.** Choose int64 logical chunk and XY region keys, fixed origin and region dimensions, voxel size, vertical extent, half-open ownership, and exact bounds derived from all multiplication/addition, collision, provider and render constraints. Define mathematical floor division/modulus at negative coordinates including `MIN_int64`; reject before arithmetic overflows. Separate logical position from local renderer origin. Document the point at which a request is outside the supported machine domain, how origin rebasing presents it, and why rebase changes no seed/sample/portal.
2. **Promote wide keys end to end.** Add Data-owned dedicated coordinate/key structs; replace `FVoxelLandChunkKey`/`FIntVector` limitations in scheduler, hash maps, jobs, completions, chunk records, world demand, preview, mesher and data consumers where needed. Keep checked explicit conversions at UE-facing boundaries, not implicit int32 casts or absolute float positions. Mesh/sample logic should use small region/chunk-local coordinates plus a validated global origin. Test reconstructed positions and shared samples at far positive/negative keys and integer limits.
3. **Specify the region planner.** On each canonical XY face order adjacent signed region keys, derive portal ID/center/radius/geometry using one versioned, domain-separated seed tuple including immutable seed/stage/provider/settings. Both sides must compute the same bytes independent of generation order. Distinguish full portal key from shortened IDs and detect collisions. Specify face/edge/corner ownership, vertical interval, out-of-domain perimeter, portal spacing, path geometry, stable IDs, tie ordering and bounded retries.
4. **Plan locally but validate the dependency closure.** Request finite plans for the regions intersecting a chunk's *entire* sample, displacement, subtraction influence, filter, mesh and capsule/roof validation footprint. Derive a finite dependency radius; include all neighbors whose geometry or noise changes those samples. Each plan must connect all its required portals/chambers/entrances, include an explicit covered feet route and use the same frozen descriptor. Candidate scratch is never a published plan.
5. **Make neighbor agreement meaningful.** Extend `VoxelLandM5PortalHandshake` and `VoxelLandM5RegionClosure` to compare full descriptor, canonical portal key and side-specific feet anchors, final global overlap samples and halo at actual voxel spacing, final route certificates, and exact region ownership. A requested connected set has a specified closure boundary and must be validated as a whole or via a proven incremental equivalent. Pairwise agreements alone do not establish global connectivity if a neighbor can fail or never load. Define bounded behavior for absent/invalid neighbors and outer machine limits; no unilateral replacement, sealed fake passage, stale result or fallback.
6. **Implement demand-driven publication.** Extend `VoxelLandWorldSettingsInit.cpp`, `VoxelLandWorld.cpp`, world state/job records and completion path with a per-world region service. A chunk waits for a matching immutable complete plan set; workers never block holding all threads while waiting for neighboring producers. Identity, epoch, required-set revision and consumer lifetime are rechecked at the publication barrier. In-flight jobs coalesce only for proven identical immutable inputs; one canceled world/consumer must not cancel other active readers. Eviction removes only idle leases. Use process-wide and per-world budgets; handle memory/work exhaustion as explicit status.
7. **Generate pockets and safe field.** Evaluate a versioned 3D noise function from global sample coordinates with independent seed namespace, not chunk-local random state. Honor frequency/threshold/amplitude, depth, roof, water and protection masks from 05. Define attachment and enclosed-void behavior, mask provenance and out-of-domain rule. Pocket contributions cannot invalidate a planned capsule route or create an unapproved surface break. An M4 full/empty classification is invalid when a cave can alter the chunk; use unknown until a proven bound applies.
8. **Apply exact overlapping sample rules.** Generate all 35³ stored sample values and necessary halos using checked shared global coordinates. X/Y/Z neighboring chunks and region faces—including negative zero-crossings, face edges/corners and after origin rebase—must compute identical samples and mesh boundary geometry regardless of request order or worker. Every relevant primitive's influence includes hard-subtraction effect beyond its physical radius plus rounding and filters. Culling/indexes must be conservative versus an exhaustive oracle.
9. **Integrate editor and server.** Infinite asset preview must request bounded regional windows and support interior/cross-section views without global prepass, while invalid nodes are diagnosed by 02. Stale requests cannot overwrite later preview or another editor. Run the same CPU/descriptor path in game and dedicated server; server must never construct render/editor/GPU resources. Keep actual runtime collision/movement test as M11 follow-up, not evidence claimed from an editor mesh.
10. **Profile and harden.** Account active region plans, sample/mesh data, jobs, index, closure validation, provider contexts, pending completions and live readers with 07's admission policy. Measure traversal/load/eviction on named target hardware; documented budget limits are proposals until measured. Safe failure on unbounded recursion, candidate/path/validation exhaustion or unsupported provider is required.

## Tests and manual checks

Write independent reference tests for region floor split/join at `MIN/MAX_int64`; region faces from either side; stable seeds under unrelated nodes, varying order/thread count and origin rebase; two-dimensional grids containing negative keys; corners, missing/bad portal, blocked protection and one failed neighbor; closure membership and lifecycle isolation. Compare all X/Y/Z overlap planes and mesh boundaries from neighboring independently generated chunks, noise on/off and smooth on/off. Include actual integration tests for waiting/publishing regions, eviction under active readers, one world cancellation and data-only operation; helper-level agreement alone is insufficient.

The human builds the project, runs M1–M5 automation and logs exact filters and platform/provider versions. In editor and game: create infinite asset with shared graph, travel far in both signs, inspect region portals/entrances and surface for multiple seeds, force streaming/eviction and origin movement, and observe explicit unsupported/budget errors. Compare plan/chunk hashes across supported hosts and worker schedules; run a real dedicated server separately.

## Completion checklist / decisions

- [ ] Wide logical keys flow through all generation, scheduling, identity and presentation boundaries; no hidden int32/global-float limit is advertised as infinite.
- [ ] Planned networks and local pockets work in regional mode, with deterministic shared portal ownership and a complete bounded publication closure.
- [ ] All required sample/mesh halos, capsule routes and roof/protection invariants are validated against actual final terrain.
- [ ] Per-world/process jobs and leases are bounded and canceled correctly; no stale/cross-world publication.
- [ ] Human editor/game/server/cook, seam, cross-host and profiling evidence is recorded.

Choose exact maximum logical range, region size, vertical bounds, portal count/placement and retry budgets, provider numeric capabilities and region-closure policy. These are versioned engineering decisions within the approved product goal; unproven algorithms must report failure rather than claim connectivity.
