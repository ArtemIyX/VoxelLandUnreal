# 08 — Nonblocking editor validation and provider-safe save

**Outcome:** Editing either finite or infinite world asset and the shared terrain graph never deadlocks or freezes the game thread while a provider works. The editor displays accurate, current mode-specific results; valid assets cook and reconstruct, and invalid or unfinished assets fail the real cook. C++ provider and graph-function authoring must work within a bounded, explicit provider contract.

## Baseline and dependencies

VoxelLandEditor.cpp contains OnObjectPreSave, graph compilation and world baking paths with thread-pool futures followed by blocking Get calls. The paused worktree contains **uncommitted, interrupted** changes adding finite/infinite factories/actions, VoxelLandWorldEditorValidation and a fail-closed world-definition cook guard. Inspect and review these edits before continuing; they are not finished or verified. Some in-flight paths avoid a deadlock by rejecting all external providers before worker execution; that is a temporary limitation, not the requested provider workflow. There is no claim that either new asset cooks or initializes successfully.

Shared graph requirements and world-specific capability checks come from [02](02-mode-capability-enforcement.md); capture, save/cook reconstruction and preview from [01](01-world-assets-runtime.md); work, provider ABI, bounded snapshots and cancellation from [07](07-shared-resource-accounting.md). The owner selected two world settings types sharing one terrain graph; finite supports global erosion and infinite rejects whole-finite-world nodes while permitting correctly bounded local/regional stages. No old-user migration is required, but preserve user-authored files and reject unknown current formats.

## Detailed implementation

1. Inventory **every** editor entry: new finite/infinite factories and details, VoxelLandEditor.cpp OnObjectPreSave, generic terrain graph and function saving, old named/control graph paths still present in the paused tree, graph compiler/schema, GraphToolkit preview, undo/redo/reload/PIE, validation and the actual cook archive. Record which calls dispatch work and any blocking Get, wait, module/provider callback or UObject/Slate access.
2. Choose a single lifecycle-owned validation coordinator. On GT capture the asset mode, immutable graph/function sources, authored settings/curves, seed, provider requirement manifest, world identity inputs and editor source revision; retain UObjects only via correct engine GC-aware owner and never dereference them off-thread. Acquire provider/module leases and a shared budget. Bound capture, including function input names, FText and soft paths: legacy function capture can call Tooltip.ToString and TryLoad reentrantly, so copied preflight alone is not a proof. Detect mutations after each potentially reentrant load and before publishing.
3. Dispatch native immutable validation and compilation work without any GT wait on an arbitrary provider. Eliminate blocking Future.Get from GT paths. Define the supported provider ABI, capability metadata, bounded work, cancellation, worker affinity and module lifetime. Treat metadata as a contract, not a mechanism that makes a blocking callback safe. If a provider needs a GT step, schedule an explicit asynchronous continuation; never synchronously wait on the GT from a worker whose caller blocks that thread.
4. Introduce per-asset validation states, e.g. Unknown, Pending, Valid and Invalid, plus epoch/revision, world kind, full source and frozen provider identity. A callback applies only if editor/module/asset are alive and all identities and revisions still match. New edits, undo/redo, provider removal, close or PIE invalidate/cancel old subscriptions. Multiple editors/worlds have independent consumers; ending one must not kill other worlds.
5. Run exactly the same world-mode graph validation used by compile, cook and runtime: inspect transitive nested/shared functions and actual provider IDs/configurations from the same registry snapshot. Finite-global stages are permitted only for finite assets; bounded local/filter/regional operations are permitted when supported by that backend. Unsupported fixed-lattice noise/provider/parameter constraints report a separate backend diagnostic, not a fabricated finite-global classification. Do not silently treat unknown requirements as local.
6. Show node/function path, mode, stage and actionable reason without marking the graph globally invalid for another asset type. Provide pending/stale state, bounded diagnostics and per-node status. Preview keeps the last valid result visibly Stale until matching graph/descriptor/plan/region revision succeeds; no invalid or obsolete compile may reuse prior bytecode as current.
7. Define save semantics: ordinary asset editing and transactions remain possible for invalid graphs, but save state must never assert a completed validation that is pending or stale. Capture only implemented authoring controls. Preserve opt-in user content; do not create or overwrite example assets as a side effect of validation or editor startup.
8. Define cook as an explicit dependency on a **completed matching validation and bake**. A commandlet cannot assume an async editor task has finished. Provide an awaited/off-GT preparation stage or bounded commandlet scheduler that does not deadlock with provider GT requirements; ensure deterministic diagnostics and target-specific provider/module leases. During archive cooking, actual failure must set archive/cooker error, not just log. Never mark preparation successful from Pending, stale or previously failed state.
9. Implement finite and infinite cooked data using the actual current descriptor/compiled graph, baked curves and required provider versions. At runtime revalidate source/manifest/capabilities and reconstruct the matching generator/region plan; cook and runtime must share the same accepted contract. Remove the provisional unconditional cook-write failure only once valid asset cook and reconstruction are implemented and independently tested. Preserve data-only dedicated-server behavior.
10. Handle cancellation and teardown: editor module unregisters actions/delegates, closes preview and cancels/drains its own jobs without touching other PIE worlds; retain provider and budget leases through actual producer capture destruction. Recheck source revision after callbacks and before marking an asset or preview current. Avoid holding locks across callbacks, waits or UObject operations. Keep no external messages or user asset mutations hidden.

## Automation to author; human runs

- Test finite and infinite asset factories, metadata, undo/redo, source/parameter edits, save/reopen, both valid/invalid graphs, nested function with a finite-global node and unknown/missing/version-mismatched provider. The same graph can be valid for finite and invalid for infinite; finite-halo filters are not banned merely for being filters.
- Provide a deterministic provider whose validation requests a GT continuation: prove editor GT remains responsive and validation eventually finishes without deadlock. Test a long provider, cancellation, provider removal, stale epoch and reentrant source mutation during each load/callback; use barriers and explicit lifetimes, not sleeps.
- Test two graph editors and two PIE worlds; closing/reloading one retains the other. Ensure a late failure cannot replace a current preview or incorrectly clear Stale. UI-only changes must not replan if dependencies are unchanged.
- Test real save event/transaction path, invalid and valid cook guard at archive and cooker process, baked curve/program/provider reconstruction from cooked data, server without editor/render modules, and missing provider error. Assert actual cooker error and process exit/log result, not merely a log line.
- Test work and memory exact/one-below boundaries, graph input with bounded/nonbounded FText/function parameters, provider callbacks/cancellation and no unaccounted arrays/leases. Run independent canonical vectors and current-format unknown-version failure.

## Exit criteria and open choices

- [ ] Both asset types are creatable; validation identifies disallowed infinite nodes and correct nested function/provider locations before generation, without blocking the editor.
- [ ] Valid finite and infinite assets complete real cooking and reconstruct in game and a dedicated-server target; invalid/pending/stale assets cannot cook and ordinary editor save remains safe.
- [ ] Real C++ providers and parameterized reusable graph functions have a bounded, nonblocking capture/execution path; restrictions are documented until actually implemented.
- [ ] Owner runs editor, game, save/cook, server and automation checks and records logs, build target, revisions, engine/compiler/platform and skips. Do not claim an asset validated from an unrun fixture.
- [ ] Resolve the bounded FText/source snapshot contract, provider async/cancellation ABI and supported error handling; the existing unconditional cook guard and external-provider rejection are not completion.
