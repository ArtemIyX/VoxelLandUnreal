# M5 numeric and identity contract: implementation proposal

**Status: proposed technical design for integration review; not verification or a published format.** The owner authorized choosing technical details and requested both regional networks and local pockets. This is a bounded candidate version, not a claim that an algorithm, migration, capsule proof, or cross-host run exists. Reconcile interfaces and choices with the parallel implementation before assigning a persistent version. Reject an input whose required proof or arithmetic is unavailable; never publish a partial plan. The 185 cm default standing height includes both rounded ends; other clearance parameters are configurable as described in the Gate A proposal.

## Baseline and version boundary

M4 uses global integer centimetres, height and some shaping in Q8 cm, and in the finite generator converts Q8 cm to `int16` units of 1/1024 voxel, rounding nearest with ties away from zero and then saturating to [-32768,32767], **before** optional Smooth Density (`VoxelLandGenerator.cpp`, around lines 1453–1493). M5 must operate on the actual stored post-filter values, and define a separate final conversion if carving requires one. Do not relabel a quantized M4 value as an exact centimetre SDF or claim smooth density is 1-Lipschitz. M4 identity encoding versions 1–6 and program encodings 1–2 remain readable with their existing byte rules. A missing or disabled cave stage follows precisely the old path and old identity: it does not add version bytes, resample, or rehash an M4 record.

Proposed opt-in IDs are **M5 descriptor 1, seed 1, topology 1, geometry 1, regional ownership 1, pocket noise 1, surface/validation 1, output composition 1**. These identify distinct contracts; unknown versions or missing historical providers are errors, never fallbacks. Version numbers here are not permission to overwrite an existing committed meaning. Once a version is used for a saved world, retain its implementation and dependency versions, or explicitly reject/migrate the world; an upgrade creates a separate identity and must not rewrite the original record. An uncached immutable plan can be regenerated from retained inputs; do not persist transient pointers, index layout or task state.

## Coordinates and arithmetic

* Logical coordinates are signed whole centimetres in int64; geometry calculations use Q8 cm when sub-centimetre precision is required. The finite or regional plan and every sample, influence, surface query, validation, filter and meshing footprint must lie in the closed arithmetic envelope `[-1,048,576, +1,048,576]` cm on each axis. Bounds use half-open `[Min, Max)`, with `Max <= 1,048,577`, and must also fit the underlying M4 domain and provider limits. The envelope includes padding; it is a proposed initial precision limit, not a claim that rendering or a provider supports the entire envelope. Reject requests that do not fit rather than wrap or silently clamp. Moving the rendering origin never changes logical coordinates, IDs or samples.
* A coordinate difference is at most 2^21 cm, and a three-axis sum of squared differences is at most 3*2^42 (<2^44). Sum using checked signed 64-bit operations. Q8 coordinates have magnitude at most 2^28; differences at most 2^29. The sum of three squared Q8 differences is at most 3*2^58 (<2^60) and fits in signed 64 bits under this envelope. Products of squared quantities, shifted numerators, and other larger intermediates can exceed 64 bits: use a portable, independently tested unsigned 128-bit arithmetic abstraction for those operations; do not assume MSVC supports `__int128`. Check every left shift, multiply, subtract, conversion, count and byte total, even where a derived bound appears sufficient. Negative inputs must not be converted to unsigned before their magnitude is checked. An intermediate that cannot be represented yields a diagnostic, preserving output.
* `floor_div(a,b)` is mathematical floor for b > 0, using quotient/remainder without negating INT64_MIN. `floor_mod(a,b) = a - floor_div(a,b)*b` belongs to [0,b); the multiply/subtract are checked. Examples for b=32: -33 -> (-2,31), -32 -> (-1,0), -1 -> (-1,31), 0 -> (0,0). Regions and noise cells use this rule, never C++ truncating division. Sample locations are derived from global integer coordinates; independently requested shared X/Y/Z sample planes use identical positions.
* Integer square root is the unique floor root `r` such that `r*r <= n < (r+1)*(r+1)` with checked 128-bit comparison. Reject zero-length segments; never divide by a zero length. All division and tie behavior must be explicit; no platform libm, float contraction, unordered iteration, pointer value, origin shift, or task scheduling may choose an ID or topology.

## Canonical random streams

The proposed portable stream is SHA-256 over an exact 61-byte packet. It is a counter-based keyed construction, not mutable per-world RNG state. All integers are fixed-width, little-endian; signed seed is its two's-complement 64-bit encoding. `FGuid` is its four `uint32` words A, B, C, D in that order, each little-endian (not host structure bytes or textual GUID byte order).

| Offset | Length | Field |
|---|---:|---|
| 0 | 8 | ASCII `VLM5RNG` followed by 00 |
| 8 | 4 | seed contract version, u32 = 1 |
| 12 | 1 | namespace: candidate=1, edge=2, entrance=3, pocket=4, regional portal=5 |
| 13 | 8 | world seed, i64 |
| 21 | 16 | stable cave-stage GUID words A/B/C/D, four u32 |
| 37 | 8 | author salt, u64 |
| 45 | 8 | stable element ID, u64 |
| 53 | 4 | attempt, u32 |
| 57 | 4 | draw index, u32 |

The word `x` is the digest's first eight bytes interpreted little-endian. A candidate owns its own ID/attempt/draw sequence; unrelated nodes or evaluation order cannot consume its stream. Different uses of randomness have distinct namespace or explicitly assigned draw slots. Draw counter exhaustion is an error; never wrap. For uniform `n` in [1,2^64-1], compute `threshold = (2^64 mod n)` using unsigned wrap equivalent `(0 - n) % n`. Draw x until `x >= threshold`, then return `x % n`; enforce an explicit work cap and fail if exhausted. For full-width range use x directly. A signed `[lo,hi]` sampler computes its width and result with widened checked arithmetic; it never negates INT64_MIN or biases by a plain modulo. IDs must be canonical and collision-checked; a hash collision is not permission to merge elements.

A regional candidate, local edge or entrance must use a **region-qualified stream**, not the generic packet alone: compute SHA-256 over ASCII `VLM5REG` plus 00 (8 bytes), regional stream version u32=1, signed region Rx and Ry (two i64), followed by the complete 61-byte generic packet, for 89 bytes total. All integers are little-endian, signed coordinates use two's complement, and the first eight digest bytes form the little-endian output word. Do not use array positions or truncate a regional coordinate into the generic element ID. Use an explicit region-qualified API; finite generic streams remain unchanged.

For proposed globally named regional features, hash this distinct 77-byte packet: ASCII `VLM5FID` plus 00 (8); feature-ID version u32=1; world seed i64; stage GUID A/B/C/D (four u32); author salt u64; region Rx and Ry (two i64); feature kind u8 (1=candidate, 2=edge, 3=entrance); and two u64 local keys. Candidate/entrance uses a stable local ID and zero; edge keys are its ascending local endpoint IDs. The feature ID is the first eight digest bytes interpreted little-endian; preserve the complete canonical input or full digest and reject unequal full keys sharing a shortened ID. Detect duplicate local IDs before edge construction. Portal identities use the shared adjacent-region packet below, not either side's feature ID. These packets and IDs must enter regional deterministic ordering and plan metadata. A changed packet or collision policy requires a new version, not an update to old worlds.

For n=10, threshold=6: injected x=5 is rejected, x=6 returns 6; x=16 returns 6. Verify one, maximum n, exhaustion and signed intervals using an independent big-integer oracle. SHA provider implementation and retention must be available in server and cook targets; absence or incompatible version is an explicit error, not a different random generator.

## Candidate, edge, and region ordering

Finite candidate IDs are monotonically increasing u64 in the planned enumeration and independently produce coordinates via distinct stream draws within the validated half-open volume. Visit in ascending ID order; compare exact checked integer squared distances with configured minimum spacing. Accepted IDs do not depend on storage order. Build all unordered chamber pairs within the explicit edge cap; normalize endpoint IDs `(min,max)`, reject duplicate IDs, and sort by `(squared_distance, min_id, max_id)`. A deterministic disjoint-set spanning tree processes that order; equal distance ties are resolved by IDs. Reject a disconnected feasible edge graph or an exceeded budget; never remove a required edge to hide failure. Loop selection is separately versioned and uses a per-edge stream; it cannot perturb candidate streams. An empty or impossible domain fails explicitly.

Regional topology requires more than per-chunk seeds. Proposed region size is a validated fixed integer multiple of the base voxel size; the same size, region-grid origin, cave-stage ID and algorithm version occur in the descriptor for every region. Region coordinates are the XY pair `floor_div(global_cm - grid_origin_cm, region_size_cm)` with checked subtraction; every region shares an explicit fixed vertical interval. Only regions and all footprints within the arithmetic and M4 provider envelope are supported; this is a finite coordinate representation, not an infinite precision promise.

For each face-adjacent XY region pair, normalize endpoints lexicographically by signed `(Rx,Ry)`. Derive its full portal key as SHA-256 of a fixed 77-byte packet: ASCII `VLM5PRT` plus 00 (8 bytes), portal version u32 = 1, world seed i64, stage GUID A/B/C/D (four u32), author salt u64, first Rx/Ry and second Rx/Ry (four i64), face axis u8 (0=X, 1=Y), all integer fields little-endian. Require both regions to agree on all descriptor and grid metadata; grid origin, spacing and vertical bounds belong to the enclosing descriptor and portal dependency key. The public u64 portal ID is the first eight digest bytes in little-endian; retain the full key or digest and reject any ID collision before publication. Neither current region's generation order nor neighbor loading enters the packet. Independent reference for seed=-1, GUID=(0x01234567,0x89abcdef,0x10203040,0xfedcba98), salt=0x0102030405060708, regions (-2,4) and (-1,4), X face: packet `564c4d355052540001000000ffffffffffffffff67452301efcdab894030201098badcfe0807060504030201feffffffffffffff0400000000000000ffffffffffffffff040000000000000000`; SHA-256 `8dad505e95b98163002956f877aa946a7a62c728c8fc6c8000fa95fbb6d34323`; ID `0x6381b9955e50ad8d`. The portal's center, radius, protected footprint and orientation are computed entirely from that shared key and immutable surface/mask inputs available to both regions, and are checked byte-for-byte on each side. A region owns its half-open interior, while the face portal record is shared logical data; each side evaluates the same analytic portal at global samples. Require every required face portal, chamber and entrance to join one connected local graph; materialize the portal at the shared boundary and retain clearance/halo on both sides. A region plan publishes only after its full footprint, every local route and each portal's immutable cross-boundary footprint pass the same final-field checks. Reject when masks, surface, domain limits, unavailable upstream input or work budgets prevent a safe portal; do not invent a replacement portal on one side. A valid connected grid of published adjacent regions has matching portals by construction, but a failed or absent region breaks available connectivity and must be surfaced as unavailable, not described as globally connected. Distinguish finite outer boundaries (no portal required outside the selected closed domain) from an unavailable neighbor inside it. Region corners do not own diagonal connections.

## Geometry and conservative queries

A tractable first kernel is constant-radius line segments plus spherical chambers, all positions/radii as integer cm and no wall displacement. For query P and segment A->B, let V=B-A, W=P-A, L=dot(V,V), D=dot(W,V), S=dot(W,W); endpoint cases use squared endpoint distance. For 0<D<L, squared distance is rational `(S*L - D*D)/L`. With each coordinate inside the 2^20 cm envelope, L,S < 2^44, so the numerator and products fit below 2^88. To obtain the floor distance in Q8 cm, calculate `isqrt(floor((numerator << 16)/L))` in checked u128; numerator shift stays below 2^104. Endpoint distance uses `isqrt(S << 16)`. For a sphere use the same endpoint distance; `Cq8 = distance_q8 - radius_cm*256`. This floor-distance approximation is within 1/256 cm of this chosen mathematical primitive, but it is not evidence that a quantized mesh contains a valid player route. Exact tie behavior is minimum Cq8, then smallest feature ID; union is order-independent.

A tapered radius, a spline, a curved tunnel or a non-spherical chamber requires a separately specified primitive/interpolation/error bound; do not silently reinterpret a constant segment. Piecewise segments must reject adjacent coincident points, account for junctions, and include all feature radii and margins in the plan bounds. A conservative index must return a superset of every primitive that can change the stored result. Hard subtraction `max(T,-C)` may alter a negative stored terrain value even outside the primitive radius, until quantization or saturation makes the contribution ineffective; radius alone is therefore not an influence bound. First use exhaustive evaluation, or prove and version a finite cutoff from the complete terrain value range, both conversion rules and saturation/rounding (plus blend, mask, displacement, meshing and halo effects); an explicit density clip is permissible only as its own identity-affecting versioned semantic. For a proven finite cutoff, round bounds outward to inclusive integer coordinates and include the full cutoff and any additional surface/filter footprint. Index traversal ordering is never semantic. Compare indexed results against an exhaustive independent reference at ties, bounds, degenerates and random fixed fixtures.

Terrain `T < 0` is solid; primitive `C < 0` is cave air. Hard subtraction is `max(T,-C)` after converting both into the *same* documented units with checked intermediates. Proposed conversion from a Q8 cm signed contribution to stored 1/1024 voxel units uses integer `(Cq8 * 4) / VoxelSizeCm`, nearest ties away from zero, then final saturate to int16. This is a second conversion after M4's quantization and filter, not a re-execution of M4's pre-filter conversion. Floor-distance error, saturation, any post-carve zero-sign convention, meshing interpolation, masks and all filters must be included in a conservative actual-field clearance and roof proof. A signed field value or sampled centerline alone does not prove that a capsule or its floor fits. The geometry kernel alone is not a complete route, entrance, water or surface validator.

## Pocket field proposal

Pocket evaluation must also use global coordinates and a separately versioned stream. A candidate integer 3D lattice has a positive period P in whole cm; cell i and fraction r use the same floor division/modulo above. Hash each integer lattice corner under the pocket namespace and map a specified 16 digest bits to a signed value in [-32768,32767]; trilinear interpolation proceeds X then Y then Z in signed int64 with Q16 weights `floor(r*65536/P)` and mathematical floor after each division by 65536. Checked period multiplication and corner coordinate increments are mandatory. The exact corner packet must encode all three signed i64 cell coordinates with an explicit fixed tag and length; it cannot hash a platform struct or squeeze three coordinates into the single element-ID field. Until that packet and threshold/amplitude units are specified, this paragraph is a design direction, not an implementable stable noise version. Classification returns unknown if conservative bounds are unavailable. Apply approved depth, roof, protection, water and attachment policies before carving; a pocket is not promised to be connected or walkable. Zero/disabled pockets must preserve the applicable prior path exactly.

## Identity, limits, and evidence required before stability

Descriptor encoding should be canonical fixed-width little-endian, with a magic, version, explicit length per nested record, bounded counts and sorted stable IDs. It must retain the full validated M4 descriptor and program/provider dependencies, world seed and domain, all stage versions, authoring graph dependencies, cave settings, masks and immutable provider data, topology and regional grid settings, capsule/validation profile, water policy, pockets, numeric ranges, and any choice affecting route acceptance or density. Strings must be length-prefixed UTF-8 or replaced by fixed IDs; booleans are 0/1; GUID words follow the stream rule; no padding or host-layout serialization. Canonicalize or prohibit floats (including NaN and signed zero); no raw UObject, pointer, map iteration order, editor layout, camera, or material belongs in the density identity. A 64-bit digest alone is not sufficient as equality evidence; retain and compare canonical bytes. Separately name full identity, source fingerprint, program fingerprint, plan dependency key, final plan hash, stage hash and chunk hash. Until exact ordered field-by-field descriptor schema, mask encoding, provider identities, pocket corner packet, validation work units and migration are specified, do not treat descriptor version 1 as frozen.

Initial capacity proposals from Gate A (256 candidates, 32,640 pair edges, 8,192 segments, eight attempts, 256 MiB and one producer per world) are unmeasured caps, not performance results; add an actual process-wide concurrency/admission cap and a bounded validation-work counter before dispatch. Check sizes before allocating, retain admission until the last worker releases scratch, and check cancellation between bounded batches and immediately before publishing. Test boundary/overflow/cancellation/failure atomicity, deterministic schedules and independent reference vectors. Test finite and regional shared faces in positive and negative coordinates, equal-distance ties, absent/failed neighbors, world teardown isolation and X/Y/Z chunk seams. Include actual filtered/quantized field, full capsule paths including junctions and entrances, protections, pockets and roof breaches. Cross-host, cook, actual server and movement validation remain unverified until the owner runs the relevant checks; this design does not claim otherwise.
