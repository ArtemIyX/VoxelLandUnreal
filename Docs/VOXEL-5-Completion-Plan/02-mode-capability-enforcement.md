# 02 — Enforce finite and infinite graph capabilities

## Outcome

A single terrain graph/function asset can be consumed by either world-definition asset. Its complete active dependency graph, selected configurations, stages and providers are validated for the **consuming world kind** at every compile, preview, cook, cooked load and runtime initialization. A finite-global operation is valid only for finite worlds; local, finite-halo and bounded-regional operations remain valid in infinite worlds when the implementation and numeric backend support them. Unknown, unbounded, missing or incompatible dependencies fail closed with the responsible node/function path.

Depends on [01](01-world-assets-runtime.md), [03](03-remove-historical-paths.md), [04](04-infinite-world-streaming.md) and [07](07-shared-resource-accounting.md). Owner explicitly chose shared graph, two settings assets, no historical-reader compatibility.

## Current state, not an acceptance claim

`FVoxelLandWorldCapabilities::Validate` and `FVoxelLandGraphCompiler::CompileForWorld` exist in `Source/VoxelLandAlgo/{Public,Private}/Graph`. Provider registration uses ABI 3 and snapshots immutable world-requirement metadata in `Operators/VoxelLandOperator.*`. The compiler uses the same frozen registry for capability checking and compile, and includes a conservative infinite fixed-lattice check. It is **not wired to every world asset/cook/runtime path**; generic `Compile` and decoded payloads can otherwise bypass target checks. The core compiler/flatten pass and provider callbacks are not fully metered. Current infinite control evaluator supports a restricted 2D Value/Fbm/scalar set, rejects dynamic parameters and cannot honestly advertise arbitrary 3D/Perlin control nodes; its renderer/local detail support must be assessed separately. The editor save/cook implementation is interrupted and uncommitted.

## Implementation

1. **Define authoritative requirements.** In dedicated Data/Algo records define world kind and a requirement manifest capable of expressing local sample, finite neighborhood plus exact halo, bounded region plus dependency radius/ownership, and finite-global/full-domain dependencies. Distinguish semantic world requirement from backend support and execution stage. Validate bounds, units, optional fields and provider versions; no implicit `SampleLocal` default.
2. **Inventory every built-in and stage.** Trace the builtin catalog, graph compiler, `VoxelLandM4StageAnalysis`, `VoxelLandM4HeightStageValidation`, fixed-lattice evaluator, Smooth Density and erosion prepass. Assign declarations justified by actual reads and halo. Erosion is currently world configuration/prepass, not an implemented graph erosion node: validate it separately as finite-only. Do not reject an operator merely because it is called a filter/global stage; reject only unbounded/full-world dependencies or unsupported semantics. Validate all relevant authored nodes and always the full active closure; specify diagnostics for disabled/unreachable nodes.
3. **Close provider trust.** Extend immutable operator descriptors/registrations so requirement for an exact provider ID/version is conservative across **every configuration** (or calculate per-node from immutable bounded config with a metered API). Freeze the exact capability, dependency version and provider/module lease in the registry snapshot used by compile *and* execution. Reject absent/invalid declarations, stale ABI, duplicate IDs, absent leases and providers whose bounded worker/validation contract is unavailable. User wants reusable graph/provider direction: do not present a blanket external-provider ban as completion.
4. **Traverse reusable functions completely.** Capture bounded native source and interfaces, resolve all function paths/IDs, nested/shared dependencies, graph edges and referenced provider configurations with deterministic sorted identities. Reject cycles, missing dependencies, duplicate stable IDs, incompatible interfaces, unknown provider or unbounded function input before producing output. Implement parameterized reusable functions—including bounded tooltip/FText capture—rather than leaving the current zero-input restriction as the final feature. No UObject access in workers. A nested forbidden provider reports both node ID and function path.
5. **Bind compile output to its mode.** Add a required world-target compile context or an immutable target/capability manifest attached to the current compiled output. The manifest covers graph/source revision, stage versions, exact node/provider requirements, configured halos/backend constraints and world kind. A payload compiled for finite mode must not be accepted by an infinite asset just because it was cached or loaded successfully. Runtime must verify source/program/dependencies and target against the same frozen provider snapshot; on any failure invalidate stale payload, do not fall back to old compiled data.
6. **Integrate all callers.** Route finite/infinite asset validation, graph schema/diagnostics, `CompileForWorld`, graph functions, editor preview, async save preparation, cook guard, cooked reconstruction, `VoxelLandWorldSettingsInit` and all direct/programmatic initialization paths through a common checker. Search generic `Compile`, `ProgramCodec::Load`, prepass preparation, example and editor tests; a generic authoring-only compile must not be a back door to world initialization. On node menu/details show incompatibility for the selected asset and preserve source for editing; provide node and nested path, not a guessed node sharing the same opcode.
7. **Check the backend separately.** Either implement the needed deterministic infinite graph operators (including parameters and bounded filters) on a specified backend or fail with an explicit backend-unsupported error. A 3D noise operation is not finite-global merely because this backend cannot evaluate it. Revalidate actual frozen parameter overrides, coordinate precision, provider limits and full halo at runtime. Do not silently select a different noise basis, clamp input, or accept a sample graph that will fail later without an actionable error.
8. **Meter and cancel.** Use 07's shared context through capability collection, function traversal, compiler flattening, provider metadata, program load and validation. Reserve all live buffers before allocation; a trusted provider has a bounded work contract. Poll cancellation inside loops and before publishing. GT capture must not block on provider callbacks. Errors carry stage, mode, node/function identity and reason; output draft/program is failure-atomic.
9. **Version and dependency retention.** Keep a single current world/program encoding and reject unknown versions or unavailable providers. Record every density-affecting mode, backend, operator requirement, function dependency and setting in the descriptor. Delete historical readers according to 03, but do not delete version checks or deterministic seed separation.

## Verification plan

Author tests for the identical graph used by both assets: local operations accepted in both, a valid finite-global operation rejected for infinite, finite-halo allowed with sufficient halo, and a nested forbidden operation plus shared functions, cycles, missing/duplicate IDs, unknown provider and changed provider configuration. Include finite-only erosion even though it is not a graph node; unsupported noise/3D/backend and dynamic-parameter diagnostics; stale compiled finite payload loaded under infinite; programmatic runtime initialization; valid/invalid cook; undo/redo and stale preview. Check node/path diagnostic accuracy when two nodes emit the same opcode. Use independent capability tables and deliberately invalid fixtures, not a second call to production as an oracle.

Do not build or run tests here. The human runs M3–M5 automation, creates the two assets referencing one graph in editor, edits a reusable subgraph to introduce/remove a finite-global node, attempts preview/cook and runtime in both modes, and records exact errors. Test a registered C++ provider and unknown provider; actual server/cook and cross-host checks are separate evidence.

## Acceptance and decisions

- [ ] The same frozen provider snapshot and source revision govern all compile/cook/runtime checks.
- [ ] Finite-global dependencies are rejected at every infinite entry, including nested functions and direct cooked input.
- [ ] Bounded filters/regions are supported when their real dependencies and selected backend are supported.
- [ ] Errors identify the actual asset/mode and offending source; invalid/stale bytecode never executes.
- [ ] Parameterized functions and provider configurations work or are reported as unfinished; no fake local declaration.
- [ ] Human validation is recorded; no tests are claimed merely because fixtures exist.

Resolve whether inactive/unreachable invalid nodes make the authoring asset invalid versus warning-only, and the first supported infinite backend/operator set. Resolve a bounded FText snapshot contract and provider callback/admission API with 07 before claiming complete function/provider support.
