# 07 — Shared work, memory, provider and lifetime accounting

**Outcome:** A finite or infinite world request admits and accounts its actual work and simultaneously live memory across graph capture, functions, providers, program validation, identity, finite prepass or regional planning, generation and final certification. Work cannot escape accounting behind callbacks, copies, queues or asynchronous completion.

## Baseline and boundaries

FVoxelLandM5Budget and its lease provide shared logical byte/work counters, bounded lease count and RAII release. Candidate, entrance, topology, index and several geometry helpers use it. M5SourceFingerprint, M5ProgramDecoder/Loader, metered program validation and curve/override checks cover limited subsets; not all provider or graph-function configurations are available. M5IdentityPreflight inventories bounded input but explicitly cannot authorize codec, registry, provider or M4 preparation. M5BoundBase::Prepare currently returns Unproven instead of calling unmetered work; PlanPreparation also does not publish a plan. Existing M4 prepass coordination uses separate admission and native/provider costs are not completely charged to the M5 meter. These are source observations, not measured performance or passing tests.

The owner requires a shared graph for two world assets, finite erosion and infinite regional caves/pockets. Old development identities/readers need not be retained. Keep one explicit current format and provider version checks; “remove legacy” does not mean allow invalid or unknown formats. Follow [01](01-world-assets-runtime.md), [02](02-mode-capability-enforcement.md), [04](04-infinite-world-streaming.md), [05](05-cave-pocket-generation.md) and [06](06-final-mesh-route-certification.md). Account render memory separately but never impose renderer/editor dependencies on the data-only server.

## A–Z implementation

1. **Define admission hierarchy.** Introduce immutable process-wide limits, per-world/request limits, per-region consumer leases and finite work units. Specify which resources count payload, container capacity, alignment, shared-pointer/control block, allocator overhead, queue/completion objects, pinned module/provider lease, native-noise worker and renderer resources. If exact allocator overhead cannot be observed, reserve a proven conservative bound plus a separately bounded object count; label estimates honestly and measure them. Never call a partial logical byte counter total process memory.
2. **Create one request context.** Capture world type, identity/version, provider registry snapshot and settings on GT; then pass only immutable native data, one explicit shared budget, cancellation token and ownership-aware leases into workers. A provider declaration and actual operator must be from the same frozen, pinned registry. One request cannot substitute a larger budget or a different descriptor after acquiring a candidate.
3. **Bound before copying.** Inspect counts and lengths with checked arithmetic and deterministic upper bounds before constructing arrays, maps, sorted indices, snapshots, writers, UTF-8 strings, graph function closure, baked curve samples or worker contexts. Bound authored object capture and strong-reference lifetime on GT. Identify operations that can reenter, rebuild FText/string-table histories or resolve soft paths; a flat cost cannot prove these bounded. Implement an explicit supported bounded capture representation and versioned comparison semantics; reject unsupported inputs until available, without calling them fully supported.
4. **Graph/function/provider path.** Trace world asset capture through function dependency closure, source fingerprints, graph flatten/compiler, registry snapshot, provider validation/worker creation, program decoder, validator and fingerprint. Meter all nested scans, sorts, duplicate checks, strings/configuration, hashes and diagnostics, including failure and cancellation paths. Count worst-case common-prefix comparisons and sort behavior; do not charge only successful work. Each external provider must have bounded declared work/memory, immutable configuration-wide capability and pinned code lifetime, or fail explicitly; never run arbitrary unmetered provider callbacks under a trusted budget.
5. **Identity and prepass.** Integrate M5IdentityPreflight, M5SourceFingerprint, M5ProgramDecoder/Loader and metered program/curve/override validation where their exact contracts apply. Replace their current subset restrictions with correct shared-function/provider support rather than describing a narrow path as full support. Refactor current world/prepass serialization to share a single canonical writer while retaining *current* deterministic bytes and atomic output. Meter writer buffers, sorted authored and reachable overrides, all source/program/provider checks and hashes. No old-format compatibility readers are required.
6. **M4 preparation.** Instrument actual control-stage validation, prepass coordinator, finite grid/erosion, local fixed-lattice generation, worker contexts and native-noise calls. Replace overlapping or disconnected M4/M5 quotas with an explicit hierarchy or prove a conservative combined bound. Charge producer and consumer attachments separately as appropriate; a grid/result is not freed while any job retains it. Infinite mode must not reserve a whole-world prepass or synthesize a finite global grid.
7. **Plan and final field.** Charge candidate rejection, stable sort/union, portal agreement, entrance surface query, masks, pockets, index construction/query, all sample/halo storage and actual mesher/triangle proof. A trusted surface/validator interface must accept the same budget; arbitrary callbacks cannot self-assert they were metered. Precharge a proven upper bound or debit each bounded batch, including negative/error paths and callbacks. Avoid full-envelope index or repeated hashing assumptions as performance guarantees.
8. **Lifetime and cancellation.** Attach a memory reservation to every immutable result until the actual final shared reader and producer capture destruction, not merely future completion. Detach an individual canceled world from shared work; cancel shared producer only after last consumer leaves. World teardown drains its own jobs; module shutdown drains module-owned services without destroying other PIE worlds. Callback results verify epoch, current full identity, revision, lifetime and budget provenance immediately before publication.
9. **Avoid starvation and reentrancy.** Never hold locks across provider calls, UObject operations, wait/join or potentially reentrant completion. Infinite neighboring region demands should not block all workers waiting on each other. Separate admission from execution, enforce process concurrency, propagate admission failures and supply diagnostics with stage and bounded work/byte detail.
10. **Current-only replacement and observability.** Remove redundant temporary compatibility writers/counters after all callers use the current contract. Emit actionable diagnostics and stage timing without per-sample log spam; make queue sizes, live/peak charges and leases inspectable in editor and headless server. Unknown version/provider/unsupported metering fails closed.

## Required tests to author

- Independent checked-arithmetic/reference model: per-stage and cumulative work, exact/one-below/overflow, memory and object counts, zero requests, allocator estimate limits, no side effects on failed admission. Distinguish actual measured bytes from reserved estimates.
- Huge nodes/pins/links/function closures, long shared-prefix names, malformed strings/configuration, cyclic/missing paths, variable provider requirements, unsupported provider, source mutation/GC/reentrancy. Confirm no unmetered FText/provider callback sneaks through.
- GT capture to async completion, actual native worker creation/use/destruction on the same thread, provider module lease retention, delayed destruction after future completion, final-reader release and no stale publication. Use deterministic barriers, not sleeps.
- Multiple worlds/PIE windows, shared prepass/region producers, last-vs-first consumer cancellation, budget exhaustion under concurrent admission, process shutdown versus world teardown, and no lock held across callback or join.
- Finite global erosion, infinite regional planning, high-volume pockets and all final mesh proof work under the same meter. Include actual graph functions and representative supported C++ providers. Fail when any stage attempts an uncharged allocation/work operation in a test provider.

## Acceptance evidence and open choices

- [ ] All producing paths use the same bounded admission contract; bytes and work remain charged through actual lifetime, including preview and cooked/server reconstruction.
- [ ] Every unsupported/unmetered provider/input produces an actionable error and no partial plan, stale chunk or false preview.
- [ ] Human runs relevant automation under editor and real dedicated server, performs multi-world cancellation and records exact binaries/revisions/configurations, logs and skipped cases.
- [ ] Record measured peak/latency distributions and target hardware, then choose process/per-world caps and cancellation granularity. Numbers in M5 proposals are starting values, not established budgets.
- [ ] Explicitly resolve FText/localization capture, external provider ABI and enforcement, allocator accounting and native-noise thread-affinity. The current partial meter does not by itself complete this work.
