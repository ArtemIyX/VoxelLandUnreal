## Execution

1. **Inventory before edits.** Record plugin/outer branch and staged, unstaged, untracked/deleted changes; obtain the owner of each interrupted source/test file before resuming. Search `LegacyFloat`, `UnlimitedBackend`, `bUnlimited`, version-dependent opcodes, `CaptureVersion`, old prepass versions, legacy named-output assignment, old asset casts, serialized payload readers and historical golden tests across Data/Algo/World/Editor/examples. Classify each hit as obsolete compatibility, current semantic feature, test, or planned removal. Preserve untracked Content and docs.
2. **Choose the current numerical behavior.** Specify finite and infinite backend, valid operations, coordinate and precision limits, seed/hash byte order, stage order and current identity versions. Finite erosion/detail/overhang/smoothing must still work. Infinite fixed-lattice support for parameters, 3D noise, local filters and providers must be implemented where required or explicitly report unsupported; do not rebrand a restricted backend as full support. The owner authorizes breaking old terrain identities, not silent inconsistencies between two executions of a new world.
3. **Complete current program cleanup.** Verify the compiler, program draft, VM, program validation and codec use the current program format and semantic version consistently, including native worker configuration and examples. Eliminate old execution/math/noise scaling branches and historic program payload readers; keep rejecting stale/unknown versions and missing provider ABI. Replace v1-only fixtures with current independent byte/reference, determinism and failure coverage; preserve unrelated tests. Check all dynamically supplied provider modules, cook and server consumers.
4. **Replace the mixed asset path.** Move common controls/graph references to the shared world-definition base; finite-only grid/domain/erosion to finite settings and regional/vertical settings to infinite. Route editor factories, initialization, bake, preview and save through the typed assets. Do not preserve a user-editable boolean/backend selector alongside type-derived kind. Remove old factories, settings switches, old graph terminal/menu and `UVoxelLandM4WorldConfig` only after all actual users/call sites have switched. The current HeightOutput graph/function path must cover the old authoring use case before named-output code is deleted.
5. **Replace saved/cooked world identity deliberately.** Define one fixed-width canonical representation for each world kind (shared prefix + explicit tagged finite/infinite fields is acceptable). Include full graph/program/provider, seed, stage, backend, erosion/cave/noise/protection/water/profile/region dependencies. Distinguish full identity, source/program fingerprint, plan key, plan hash and chunk hash. Use exact endian, lengths, sorted keys and float normalization; compare complete canonical bytes when collision safety matters. An infinite descriptor must not synthesize a finite global prepass or require one finite XY cave domain. Reject malformed, unknown or unavailable current versions explicitly. Existing development saves may require recreation; report them, do not silently modify user assets.
6. **Remove only obsolete compatibility state.** Remove `CaptureVersion` overloads and old version-dependent branches that have no current role; collapse old 1–6 identity / 1–4 prepass paths consistently, including tests and cache keys. Keep the *current* format identifier and validation of it. Remove obsolete `LegacyFloat` enum/config/worker dispatch and legacy direct-generation helpers once fixed local generation and explicit errors exist. Preserve headless CPU and M4 finite behavior except where the owner-approved current format explicitly changes identity.
7. **Audit all dependencies.** Search after edits through Source, tests, examples, plugins and docs; inspect every remaining occurrence in context. No old symbol may be dangling in generated/reflection code, serialized data, plugin descriptors, scripts or editor UI. Remove misleading compatibility comments/doc promises; retain historical M4 acceptance record as evidence, not an assertion that the new code was retested. Ensure no user `Content/`, FastNoise checkout, staged/untracked file or root-project documentation is discarded.
8. **Finish in cohesive slices.** Assign one owner per shared file, coordinate program vs identity vs runtime/editor work, format changed C++ using the repository style, conduct read-only reviews for semantics, versioning, overflow, lifetime and module boundaries, and commit scoped `VOXEL-5` changes with detailed bodies only when requested workflow permits. Never build or run tests: human executes them after implementation.
