**Status:** Planning baseline, 22 November 2026. This directory is a work plan, not an implementation or verification claim. The VoxelLand plugin worktree was on branch `VOXEL-5` at `c8218543c4bd50e8b123818343c4adc6208c28a2` when these documents were written. The outer project was on `DEV-1`. Inspect both worktrees again before implementation: the plugin has interrupted, uncommitted edits, including removal of `LegacyFloat`, editor factories/validation and associated tests. The outer project has independently modified/deleted/untracked files. Preserve all existing work, inspect each diff, and integrate or deliberately revise it with ownership established; do not reset or indiscriminately stage it. Branch and revisions may have changed by the time this plan is used.

## Owner decisions and governing requirements

1. Two concrete world-settings asset types: finite and infinite-style. Both share one terrain graph and reusable subgraph/function workflow. Finite worlds support bounded global stages, including erosion. Infinite worlds support chunk-local and bounded-region generation and reject any dependency requiring a complete finite world.
2. There are no existing users to migrate; remove historical readers, compatibility branches and the `LegacyFloat` path deliberately. This supersedes earlier documents' old-world compatibility instructions. Keep explicit current-format versions, exact deterministic identities, error checking and rejection of unknown/corrupt data. Do not delete unrelated authored assets or user's work. Identify development assets needing recreation.
3. Both modes must support planned cave networks and optional noise pockets. Regional connectivity must use deterministic shared portals and matching, validated neighboring plans; rejecting unsupported work is a safe temporary result, not completion.
4. Smooth negative-solid/positive-air terrain is generated from seed, graph and settings; CPU generation is deterministic and order-independent, with a data-only dedicated-server path. Runtime terrain editing is outside v1.
5. M4 was accepted by its owner based on their reported evidence. Its deferred cook, real dedicated-server, cross-host, wider-world and documented multi-seed checks were **not** newly verified. M5 is incomplete: its initialization and plan publication must not claim success until the final field, route and roof proofs are complete.
6. The owner will build and run tests. Until instructions change, author meaningful automation and perform static review, but do not run builds or tests. A later human report is evidence only for the cases and revisions actually exercised.

The owner approved the Gate A proposal as the basis for implementation and requested configurable values. Its starting capsule profile is 185 cm total standing height, 35 cm radius, 45° maximum slope, 45 cm maximum step and 10 cm clearance margin. Its proposed initial topology is 8–24 chambers, two entrances, 0–3 loops, 250–400 cm tunnel radii and 500–1000 cm chamber radii; pockets default disabled. These are configurable starting values, not evidence that any generated mesh meets them. The later requirement to support regional networks **and** local pockets in infinite mode supersedes the proposal's finite-only-first limitation. Proof tolerances, exact numerical algorithms and measured budgets remain engineering work.

## Non-negotiable integration checks

- A world asset's class determines mode; no independent editable flag can contradict it. Graph/function/provider requirements are checked transitively from the **same frozen registry** on authoring, compile, preview, cook and runtime load. Unknown capability is an error. A fixed-lattice/backend limitation is reported separately from a finite-global requirement.
- A runtime world request owns a native immutable descriptor and an identity matched to its generator, surface and complete plan-set. Capture UObjects on the game thread; worker jobs retain only native snapshots and provider/module leases. `BeginPlay` stays inert; a manager explicitly requests initialization.
- A finite world validates its entire bounded upstream footprint before global allocation. An infinite world has no whole-world prepass; it requests bounded regional dependencies. Logical positions use checked signed 64-bit or wider indices and mathematical floor for negatives; render rebasing cannot affect logical identity or sampling. State practical integer/provider/render limits rather than promising literal infinity.
- Density composition uses global samples, the existing sign convention and the selected current stage order. Existing M4 quantization precedes optional Smooth Density; any later cave conversion is separately specified and included in proof. Classification must never use an M4-only uniform shortcut when caves or pockets can change the result.
- Protection takes precedence over openings. Full hard-subtraction influence can extend beyond primitive radius; conservatively include quantization, saturation, filter/mesh halos and every relevant source sample. Separate planned-network and pocket masks. A height grid alone is not proof of a final surface with detail, filtering or overhangs.
- Publish an immutable plan/index/chunk only after the exact descriptor, dependencies, full required region set and final-field certificate match. No old preview or old task may be relabeled current. Cancellation/teardown of one PIE world never cancels another; drain actual producer captures before releasing leases.
- Admission covers input captures, providers, compiler/codec, prepass, planning, validation, index, mesh, completions and active readers at world and process scope. State and measure any allocator/native overhead separately. Reject integer overflow, unavailable bounds, zero/invalid budgets and exhausted work before unsafe allocation or publication.

## Definition of done

All eight plans' implementation and verification checklists are complete, each claimed behavior is traceable to source and acceptance evidence, and both asset types work from authoring through cooked reconstruction and explicit runtime initialization. Every planned route and entrance meets the configured capsule/floor/slope/step contract on the final mesh, with no unintended surface breaks and no protection breach. Noise pockets follow their stated connectivity, depth, water and mask policy. Finite erosion works; infinite regional networks and local pockets work without a global finite prepass. Cross-host, cancellation, seam, lifecycle and real dedicated-server evidence is recorded. An attractive preview, a self-consistent hash, a partial helper, an `Unproven` result or editor NullRHI alone is not acceptance.
