# M3 noise and native operators

This document describes source interfaces that have not been built or executed yet. Native noise uses FastNoise SSE2 on supported x64 platforms; VM scalar selection does not provide scalar native noise. Version-2 programs set the native node feature scale to 1, so graph frequency is applied once in inverse cm. Version-1 programs retain the earlier native default feature scale of 100 and their existing output semantics.

## Noise node pins

Perlin, Perlin fBm, Value and Simplex each have 2D and 3D forms. Pins are ordered `X`, `Y`, optional `Z`, `Frequency`, `Octaves`, `Gain`, `Lacunarity`, then the float output. Coordinates and frequency are floats; octaves is int32. Uniform settings accept an unconnected default or a direct parameter reference of the matching type, not an arbitrary per-sample expression. Frequency must be finite and positive; octaves must be 1-16; gain must be finite and in [0,1]; lacunarity must be finite and at least 1. Per-node GUID and salt identify independent seed slots. All four settings are validated even for non-fBm families.

Value and Simplex use distinct FastNoise metadata nodes; neither aliases Perlin. Native backend creation fails if the requested family or SSE2 is unavailable. Cross-host output and metadata availability still require actual verification.

## Native provider contract

`IVoxelLandOperator` and `IVoxelLandOperatorWorker` in `Operators/VoxelLandOperator.h` define scalar operators. Providers register a stable GUID and positive semantic version, 1-3 typed inputs and one typed output. Inputs are SoA arrays of float or int32 and outputs use a checked typed writer; bool uses exactly 0/1. Config bytes must have a canonical provider-defined representation and pass validation. The provider must be immutable and deterministic, avoid UObjects and global mutable state, declare a conservative worker-memory bound, and allocate/use/destroy worker state on the invoking worker. Count is 1-256. Kernels report errors and must reject invalid domains and non-finite outputs. The worker enforces finite float and strict bool outputs.

Register with the owning module name. Modular Windows builds acquire an OS library reference with LoadLibraryW; Linux builds use Unreal's dlopen-backed module handle. Each reference is released when its provider lease ends. Other modular platforms reject registration until their handle ownership is implemented. Monolithic builds use resident code. A module must not rely on destructible module globals in an operator or worker after shutdown. Unregister before module shutdown; unregister fails while programs or workers retain the provider. Keep the module loaded and drain work before unloading; failed unregister during shutdown leaves the code lease pinned. Programs serialize operator GUID, version, signature, seed slot and configuration bytes, and resolve and validate providers on load. Missing providers, mismatched signatures, oversized tables and rejected configuration fail explicitly. Provider memory accounting is a contract: the framework cannot measure allocations hidden inside arbitrary provider code. Providers may opt into four-lane SSE2 with `SimdRequirement` and an `EvaluateSimd` worker implementation. Selection occurs when each worker is created only if the VM SIMD backend is enabled and supported; otherwise the scalar implementation is used. Separate worker-owned scalar and SIMD contexts prevent SIMD scratch changes from affecting the reference context. For each batch the runtime computes scalar output first, then evaluates full four-sample SIMD groups into isolated scratch and compares output bytes exactly. Any mismatch or SIMD-only error logs a warning, disables that worker's SIMD kernel and retains the scalar output; tails and later batches use scalar. Scalar errors remain errors. This conservative dual execution adds cost and does not establish a speedup. Providers must declare a per-context memory bound; the budget reserves space for both contexts.

`VoxelLandSquareOperatorId()` identifies the example operator in `VoxelLandAlgo`: version 1, float input, float output, empty config, and deterministic scalar square and an optional SSE2 implementation. The graph editor offers it under **C++ extensions** when that provider is registered. Windows editor automation covers scalar and SIMD behavior, serialization and provider compatibility; dedicated-server and cross-platform behavior remain unverified.

Project plugins can add editor presentation separately from their runtime provider. In an editor-only module that depends on `VoxelLandEditor`, include `Graph/VoxelLandEditorOperator.h`. After registering the runtime provider, fill `FVoxelLandEditorOperatorPresentation` with the same GUID and version, category, display name, tooltip, ordered input names/types/defaults, output name/type and canonical default configuration. Call `FVoxelLandEditorOperatorRegistry::Register` on the game thread and report the returned error. The registry checks the runtime signature and configuration and copies the descriptor; it does not retain the project module's callbacks. Call `Unregister` for that GUID/version when the editor module shuts down, before unregistering the runtime provider. Menus hide providers that are no longer registered, and compiled programs still reject missing or incompatible providers. Inputs are currently limited to one to three, matching the compiler's external-operator support. The descriptor is covered by Windows editor and automation checks; provider-module unload and dedicated-server behavior remain unverified.

The operator framework binary and registry state remain pinned for the process lifetime on modular builds after the first successful registration. This deliberately avoids releasing its own executable code while a late program or worker destroys a provider. Hot reload may retain the old module image until process exit.

## Power

Power accepts a finite positive base and finite positive exponent, or zero with a positive exponent. A negative base requires an exactly integral exponent in [-32,32], including zero. Invalid domains, non-finite inputs, and binary32 overflow return an `InvalidMathDomain` evaluation error; invalid constant expressions are rejected by compilation. Results below half the least binary32 subnormal round to signed zero.

The implementation decodes IEEE binary32 bits and decomposes the absolute base into a binary exponent and a mantissa in [1,2). It evaluates log2 using the first 20 terms of the atanh series with `t=(m-1)/(m+1)`, multiplies by the binary64 exponent, evaluates the fractional exponential using 20 Taylor terms, and explicitly packs the approximated result into IEEE binary32 with nearest-even rounding. The logarithm's exact-arithmetic series remainder is below 2e-20 on that interval; floating-point roundoff, exponential truncation, and cancellation are additional error sources. The binary32 result is rounded from the approximation and is not guaranteed to be correctly rounded from the exact real power. Near an overflow, underflow or quantization boundary, small approximation or host arithmetic differences can affect the result. Exact-bit subnormal decoding/packing does not force the rest of the VM to preserve denormals under host flush-to-zero modes.

Power executes through the scalar reference kernel even when the VM selects SIMD. Precise floating-point settings and fixed operation order are intended to reduce host differences, but no cross-platform bit equality or error bound has been established. Windows automation exercised reference, domain, subnormal and scalar/SIMD cases; cross-platform parity remains unverified.

## External one-cell filters

Providers can return `EVoxelLandOperatorStage::OneCellFilter` and register one float density input and one float density output. Such a node must feed Density Output directly and have no other consumers; chaining filters is rejected. Its `IVoxelLandOperatorWorker::EvaluateFilter` receives a read-only, x-major quantized 37³ halo and a bounded output range in the x-major 35³ chunk. It must write deterministic int16 results, poll the supplied cancellation callback, retain no views, and produce each result only from its local neighborhood, configuration and node seed, independent of output index, call history and chunk generation order. Filters are translation-invariant: global coordinates and position-dependent behavior are not part of this interface. Worker creation receives the same stable node-derived seed and validated configuration as sample operators; workers are created and destroyed on their owning worker thread. This initial filter stage is scalar; SIMD filter kernels and composed halos are not supported.

The `Example X Average Filter` provider averages three quantized neighbors along X with integer rounding. It is available in the graph editor under C++ filters. The serialized operator table stores stage, stable ID, version, signature, configuration and seed slot; the program stores the filter index and includes these in its fingerprint. The compiler and validator can share an atomically captured provider registry snapshot, which pins providers until their users release them. Missing or incompatible providers and unsupported stages fail explicitly. Compiler semantic version 4 requires existing v2 graph payloads to be recompiled and saved; version-1 program fingerprint and execution semantics remain unchanged.

The C++ provider interface uses `FVoxelLandOperatorOutput`: write each output lane exactly once using the matching float, int32, bool or int16 density method. Four-lane checked methods support SIMD computed into provider-owned scratch. Wrong types, invalid booleans, non-finite floats, duplicate/out-of-range writes and incomplete batches fail before downstream evaluation or chunk publication. SIMD output is checked against scalar output and a mismatch disables SIMD for that worker. This is a source/ABI change: external provider modules must be rebuilt against this version; old provider binaries are not compatible.

Provider modules must call `FVoxelLandOperatorRegistry::RegisterV2` with `ProviderAbiVersion` and implement the checked-output worker interface. The old `Register` export was removed, so binaries built for the former raw-output interface cannot bind to this version; rebuild providers from source. A mismatched ABI argument is rejected before the registry calls a provider virtual method.
