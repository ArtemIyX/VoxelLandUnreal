# VoxelLand M3 authoring guide

This guide describes the current implementation. Windows editor, automation and a scoped cook have been exercised; dedicated-server and cross-platform acceptance remain open. See [M3_Verification.md](M3_Verification.md) for the pending checks and [M3_Operators.md](M3_Operators.md) for noise and C++ operator contracts.

Create a **VoxelLand Terrain Graph**, **VoxelLand World Settings**, and optional **VoxelLand Material Setup** in the Content Browser. Assign the graph and a seed, voxel size, optional material setup, and parameter overrides to the settings asset. The material setup contains one surface material; absent or unsuitable runtime materials fall back to the engine surface material. No material palette or terrain collision is included.

Open the graph. The Graph tab provides searchable context actions and left-to-right typed pins. The Details / Parameters tab adds float, int, and bool parameters. Select the graph background to edit declarations, and select a matching parameter-reference node to set its stable parameter GUID. Parameter names must be unique ASCII identifiers, ignoring case. World overrides identify the parameter by GUID and must match its type and range. Add and Multiply support adding an input from their node context menus. Right-click a particular input pin to remove it or move it up or down; removal breaks that input's connection, while reordering preserves pin IDs and remaining connections. At least two inputs must remain, and input order is significant.

The plugin content folder **VoxelLand Content / Examples** contains `DA_M3_Hills`, `DA_M3_WorldSettings`, and `DA_M3_MaterialSetup`. Enable **Show Plugin Content** in the Content Browser if needed. The graph combines a Perlin 2D branch with a separately seeded fBm 2D branch, then uses Height to Density and Smooth Density. Its typed parameters are `Amplitude` (float), `Octaves` (int), and `SmoothingEnabled` (bool). The settings asset references the graph and material setup, with seed 1234 and a 100 cm voxel size. Noise coordinates are in cm and frequency is inverse cm. Negative density is solid. Node GUID and salt affect the noise seed; changing node positions does not.

The editor automation helper `VoxelLand.Examples.Create` can create these assets in an empty plugin `Content/Examples` folder when launched with `-VoxelLandCreateExamples`; it refuses to overwrite any existing example package. `VoxelLand.Examples.Verify`, launched in a fresh editor process with `-VoxelLandVerifyExamples`, reopens the saved assets and checks their settings, compiled program, independent noise seed slots, and a generated chunk hash. Both helpers are explicit opt-ins and otherwise skip without changing assets.

For example, with a development editor build, run the following commands in separate processes, substituting the engine and project paths. The creation command is only needed when all three example packages are absent.

```powershell
& '<UE>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' '<project>/VoxelLandExample.uproject' -unattended -NullRHI -nosplash -VoxelLandCreateExamples '-ExecCmds=Automation RunTests VoxelLand.Examples.Create;Quit' '-TestExit=Automation Test Queue Empty'
& '<UE>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' '<project>/VoxelLandExample.uproject' -unattended -NullRHI -nosplash -VoxelLandVerifyExamples '-ExecCmds=Automation RunTests VoxelLand.Examples.Verify;Quit' '-TestExit=Automation Test Queue Empty'
```

A single Smooth Density node may sit directly before Density Output. Its density input is the pure field; Enabled and Strength accept defaults or direct bool and float parameter references. Strength is in [0,1]. The filter evaluates a 37-cubed source lattice for each 35-cubed chunk, uses a one-cell 27-sample box filter over quantized density, and blends with uint16 fixed-point strength. Disabled and zero strength use the original field. Do not chain filters or consume a filtered intermediate elsewhere.

Use Compiler Results to compile and inspect errors. Saving attempts to compile the source and stores a versioned program with source and program fingerprints. Version-2 payloads also store a compiler semantic version; graphs saved with an older compiler must be opened and saved again before runtime use. A failed compile leaves the graph editable and the old preview labeled stale; runtime initialization rejects stale or invalid payloads. A Windows cook of an empty invalid graph failed with a missing-output error; other invalid-graph cases still need verification. Power supports positive finite bases and exponents, and bounded integral exponents for negative bases; its numerical contract and unverified cross-host limits are documented in M3_Operators.md.

The Preview tab provides a seed, a material selector, a world-settings selector, bounded XY/Z radius, transient settings and overrides, and camera controls. Use Frame terrain or press F while the preview viewport has focus to frame the displayed chunks; Reset camera restores the initial view. If the preview is stale, framing uses the terrain currently displayed. Selected settings are duplicated for preview, so adjustments there do not save back to the asset. Preview chunks are generated and meshed on the CPU, then displayed through Unreal's render pipeline. The status reports stale, compiling, generating, error, or ready and displays CPU and render-thread fence observation timings; GPU completion is not measured. Material changes update the existing preview rather than rebuilding density.

At runtime, place a VoxelLandWorld actor and explicitly call `InitializeFromSettings` after BeginPlay from a manager or Blueprint. A true return means the asynchronous request was accepted, not that generation has completed. Observe `OnInitializationFinished`, `bInitializing`, and `LastInitializationError`; `CancelInitialization` cancels a pending request. No generation starts automatically in BeginPlay. The request copies graph, program, settings and overrides before worker execution; a changed source or settings snapshot rejects the result. A dedicated server uses the data-only path and skips material loading; its actual target build and module loading still require verification. `Shutdown` tears down generation.
