# M5 final-field validation and regional boundary design

This is an implementation design, not evidence of a passing validation or a collision implementation. The owner has selected configurable cave settings and has requested regional networks and local pockets in chunk-local worlds. Concrete numerical choices, data layouts and provider versions must be recorded with their implementation. Fail closed wherever a conservative bound below cannot be established; an attractive mesh or sampled centerline is not an acceptance result.

## Existing field and mesh facts

- `VoxelLandGenerator.cpp` generates M4 height, optional detail, slope normalization and overhang into Q8-centimetre density, then rounds to nearest with ties away from zero and clamps to `int16` density units of 1/1024 voxel. Finite demand validates the complete horizontal footprint; slope normalization adds another horizontal stencil. The fixed-lattice/local path must be checked independently rather than assumed identical.
- `VoxelLandSmoothDensity.cpp` operates on the already quantized values using a 27-sample box average, fixed-strength blend and integer rounding. Its 37-cubed input supplies the one-sample halo for the 35-cubed stored block. An external filter is a separate path with potentially different bounds and is unsupported unless its complete dependency and error bounds are available.
- `VoxelLandMeshing.cpp` considers only `Q < 0` solid; zero is air. It averages sign-changing edge intersections into one Surface Nets vertex per mixed cell, snaps vertices in global cell space and emits triangles for chunk-owned edges. It discards zero-area triangles. Stored blocks overlap and contain global samples at local indices -1 through 33; cells extend through local -1 through 32. Validation must use the same LOD, floating-point/snap semantics, triangle ownership, conversion to component space and world origin as rendering, including representability limits.
- M4 accepts height detail, overhang and smoothing; a height grid alone is not the rendered top surface. A second conversion after an M5 carve, if used, needs an explicit unit, overflow, sign, saturation and tie contract. Its effects cannot be inferred from the first conversion. The existing no-M5 path, hash and identity remain unchanged.

## Candidate publication protocol

1. Capture a UObject-free immutable snapshot containing the M4 program/provider lease and height inputs, all cave/pocket/protection/water settings, validation profile, coordinate and rendering limits, world seed, region/plan keys and algorithm versions. Validate all inputs and every requested sample footprint before allocation. An unknown filter, provider, surface interpretation, LOD or out-of-domain footprint is an error, not an invitation to reuse an earlier plan.
2. Construct a candidate with stable feature IDs and a route graph covering **all** chambers, edges, branches, junctions and entrances. Each route has an explicit piecewise path for the capsule's feet and a declared transition to each connected feature. A chamber is not certified merely because a single tunnel enters it: every required incident route must connect by a validated path across the chamber. An isolated chamber is rejected. The 185 cm standing height includes both hemispherical ends; radius, slope, step and margins are configurable profile fields.
3. For each affected chunk plus its complete dependency halo, compute both the M4-only stored samples and the *final* candidate samples with the actual production pipeline: base conversion, enabled filter, carve, optional pocket, masks and final conversion. Generate in a private validation scratch context, using the same immutable inputs and worker-affine providers as eventual chunks. Render, runtime and validation must share this single final-sample implementation; independent tests must not share its oracle. Do not classify chunks by corners. Enumerate the entire conservative primitive/noise influence volume plus mesher, filter and validation halo. For hard subtraction `max(T, -C)`, this is **not** just the physical interior or radius of a primitive: `-C` may change a deeply negative terrain value outside the cave. Define and version an explicit influence cutoff or derive a conservative bound from terrain and density saturation, prove samples beyond it cannot change after conversion, and include its complete extent; otherwise enumerate the entire permitted domain or reject the budget. Apply the same rule to pockets and all masks/blends. Compare duplicate global samples exactly across all overlapping blocks, including negative X/Y/Z. A mismatch fails validation.
4. Build the actual M4-only and candidate Surface Nets triangles for all affected cells, including edge-owned neighbors and every cell needed for closed boundary checks. Account for snap, floating conversion, winding, degeneracy and missing faces. Validation operates on the resulting production geometry, transformed back into the same global frame, not an ideal primitive SDF. Bound or reject any floating-point conversion uncertainty with directed conservative interval arithmetic; a value within the uncertainty interval of a threshold is **unproven**, not success. If the runtime later changes meshing, conversion or precision, bump the validation/geometry contract and invalidate the plan.
5. After the checks below succeed, check cancellation, snapshot identity, generation epoch and consumer lifetime again. Only then publish an immutable complete plan/index and allow its matching chunks. Error, cancellation, resource exhaustion, provider loss and stale completion preserve the prior output and cannot publish a partial network. Workers never capture mutable UObjects or widgets.

This initial exhaustive design may be expensive; skipping cells or routes is not a permitted optimization. An acceleration index may reduce tests only if conservative bounds prove it never omits a triangle, sample, protected cell or influencing primitive; compare it with exhaustive scanning. Chunk-local on-demand execution requires a bounded validation volume for each region and an explicit admission policy before publishing anything dependent on that region.

## Walkability: a certificate for the rendered final mesh

Use a conservative **geometric route certificate**, not a claim about the later M11 movement solver. Define a configurable profile `(radius R, total height H, floor slope limit, step limit, clearance margin M, geometric error E)` with finite validated values, `H >= 2R`, and positive `R`. Inflate the swept clearance capsule to radius `R+M+E` and total height `H+2(M+E)` about the same center. E includes bounded sample/quantization, mesher snap, world/component conversion and predicate errors; it is not zero merely because sample values are integers. Record the derived bound and inputs in the certificate/identity.

Represent each required feet path as bounded line segments with explicit piecewise-planar supporting floor patches. For each segment, require continuous support over its entire parameter interval. The support certificate must cover the complete projected contact footprint at every point, with a connected chain of nondegenerate, consistently oriented floor triangles; bound each triangle's actual slope against the configured maximum, validate joins and all height discontinuities against the step limit, and include endpoints, entry/exit transitions and junctions. At a permitted step, specify an explicit swept transition that fits within the step height and clears the obstacle; a line through a vertical face is not proof of a climb. Reject holes, overhangs over the feet path, unsupported gaps, ambiguous or nonmanifold support and insufficient headroom. A less capable first validator may reject steps altogether, but must report that restriction rather than claim the configured maximum step was exercised.

For every path segment and its transitions, sweep the vertical capsule continuously against **every** potentially intersecting triangle, including end caps and triangles selected for support. Support triangles receive no blanket exemption: independently prove that the nominal capsule never penetrates them and that every contact is confined to the explicitly certified floor-contact region, with supported normals and position throughout the interval. For the inflated capsule, define a bounded floor-contact allowance which permits the intended supporting contact without permitting walls, protrusions, ceiling or non-contact parts of the same triangles to penetrate the clearance envelope. Test all triangle portions outside that allowance with the same inflated clearance rule as other obstacles. Inclusive contacts elsewhere fail. If this separation or predicate cannot be proven conservatively, reject as `Unproven`. Split at segment bends and test the full turning envelope; cover vertical segments and coincident endpoints explicitly or reject them. Prove the predicates over the whole continuous interval, not an unbounded number of sampled stations. If using subdivision, certify each interval using a verified Lipschitz distance bound and outward-rounded arithmetic; recurse deterministically until certified, failed, or a finite depth/work cap is reached. Exhaustion returns `Unproven` and rejects the plan. Reject degenerate triangles that border the certificate or can compromise closure; do not assume the mesher's dropped triangles form a safe floor.

The certificate establishes geometric clearance and support only for the defined capsule and path. It does not establish navmesh connectivity, an NPC system, character movement behavior, collision response, network movement or cross-host identity. Those remain separate checks. An entrance route must extend from a connected underground route to a certified standing location outside the baseline surface and cover its full capsule envelope.

## Surface, roof and protection

The baseline is the actual M4-only meshed field, including enabled detail, overhang, smoothing and the initial conversion. Treating the highest height-grid sample as that surface is invalid. Build a conservative region around the complete baseline surface, including every disconnected surface component and closed cavity, not just the topmost crossing. Measure roof thickness against the baseline mesh in world units using a conservative lower bound on distance; ambiguous inside/outside classification, open/degenerate baseline mesh, insufficient sampled halo, or an unsupported multiple-crossing case returns `Unproven`. The validator may initially reject such configurations, but must identify which feature prevented proof.

Outside recorded entrance opening volumes, require the final field to preserve all baseline **solid** points in the protection/roof region. A practical sufficient certificate is stronger: enumerate every cell *volume* intersecting the expanded protected/roof volume, whether the baseline or final cell emits triangles or neither does. In particular, a baseline all-solid cell changed to all air emits no triangles and must still fail. Include every sample of those cells, plus all neighboring cells and samples capable of contributing a Surface Nets triangle intersecting the volume, and require baseline and final quantized values to be identical at all of those samples. Because the same mesher and snap inputs then apply, those cells retain their signs and produce the same local geometry; explicitly handle cell/edge ownership and chunk seams. Samples equal only at cell corners do not prove continuity for a different mesher or a post-carve filter. Expand the protected volume by the full cell diagonal and the bounded snap/conversion error, or compute tighter conservative cell-volume bounds. Check that the complete changed-cell influence, including the full hard-subtraction cutoff or saturation bound, cannot intersect the roof/protection volume. This may reject safe candidates; it must never accept an unproven one.

For explicit protection masks, define a cell as protected whenever any part may be protected under the mask's documented interpolation and threshold; if unknown, mark the entire cell protected. Test the final sample and triangle influence region, not merely primitive centerlines. Do not let pockets, entrance blending, filtering or quantization override protected solid. If the planner cannot find a valid route around protection, return its feature ID and reject. The unprotected default must be explicit and does not imply future road or POI integration.

An entrance has a stable ID, a bounded opening volume and connected route. The entrance exception applies only to changed geometry inside that recorded volume and only if it does not intersect protected solid; crossing outside it fails. Require the opening volume and its complete influence halo inside the planning domain, verify baseline-to-final changes against this exception, and verify the opening is reachable from both sides. Closed domain boundaries remain protected, except an explicitly modeled region portal. A hard carve is monotone in density before conversion, but monotonicity alone does not certify mesh topology, untouched roofs or passage support. Include pockets, any enabled water policy and all later operations in the final checks.

## Regional networks and local pockets

Chunk-local mode cannot use a world-wide finite prepass. Partition logical space into bounded integer-aligned regions with half-open ownership and mathematical floor division for negatives. Define every shared face by a canonical unordered pair of adjacent region keys; derive each candidate portal's position, shape and stable ID solely from that face key, the immutable shared world descriptor and a distinct portal seed namespace. Both regions independently construct identical portal geometry, corridor overlap and global-sample values. A region's planner must connect all its accepted portals, chambers and entrances into a single validated route graph; no edge may terminate at a portal that the neighbor does not agree to publish. Face, edge and corner ownership, halo footprints, allowed vertical interval, candidate count, rounding and tie rules must be specified as part of the numeric contract. A face portal must not extend outside both regions' supplied dependency footprints.

Portal eligibility must be decided symmetrically using only the bounded shared inputs needed by *both* sides, including final-surface/protection/water constraints. Each side validates the same corridor with a dependency overlap wide enough for all M4 sampling/filtering, meshing and capsule/roof tests. A portal record is publishable only after both adjacent region certificates agree on descriptor, portal ID, overlap samples and connected routes. A mismatch, unavailable neighbor, over-budget region or invalid side returns an explicit failure; it must not degrade to pockets or silently cap the tunnel at the boundary. Canceling one consumer may not invalidate another consumer's leased plan.

**Important unresolved feasibility:** pairwise validated portals alone do not prove global connectivity or avoid cascading failure when a region cannot connect all portals. A finite streaming frontier with independently rejected neighbors cannot guarantee an infinite connected network. Before claiming regional connectivity, specify the required connected component, admission/handshake closure and deterministic behavior when a neighbor fails. Either construct a bounded requested region set and validate its complete connected graph atomically, or prove an analytic region construction that always connects every eligible face under the stated surface, protection and resource constraints. No finite-radius algorithm may claim that arbitrary unbounded regions are globally connected without such a proof. The implementation must expose an explicit unavailable/failed region rather than publishing an unvalidated boundary.

Local pockets use a separately versioned, global-coordinate 3D field, not per-chunk random streams. They require finite influence and sample domains, precision/overflow limits, seam-equal samples and the same roof/protection and final mesh validation. Pockets may be disconnected but cannot invalidate certified routes. Each region must include pocket influence across its boundary and the complete neighbor halo. Water availability and permitted flooding are explicit settings; a missing required mask or water input is an error.

## Work bounds, cancellation and diagnostics

Before allocation, checked arithmetic must bound affected region and chunk counts, halo sample counts, stored density bytes, triangle/index bytes, candidate/edge/portal counts, route-support certificates, swept triangle pairs, interval subdivisions, roof/protection comparisons, worker scratch and pending completion memory. Admit both per-world and process-wide budgets. A process limit is not supplied by multiplying independent per-world maxima without overflow checks. Charge a deterministic work unit for each sample, cell, triangle pair, interval split, region handshake and query; stop at a versioned bounded cap with `BudgetExceeded` rather than return success.

Check cancellation at bounded row/batch intervals during sampling, smoothing, carving, meshing, index construction, triangle sweeps, mask/roof checks, portal agreement and immediately before publication. A canceled consumer detaches from shared work; cancel a shared producer only after its last consumer detaches. Leases cover worker/provider lifetime and completion, including stale callbacks. Failures report stage, region, feature or portal ID and reason (`InvalidInput`, `Unsupported`, `OutOfDomain`, `Unproven`, `Blocked`, `BudgetExceeded`, `Cancelled`, `ProviderUnavailable`, or equivalent existing codes). Define deterministic ordering for concurrent errors if a single error is surfaced. Do not emit logs per sample.

## Independent verification to author, not results

- Analytic flat-floor and axis-aligned box tunnels: independently compute capsule/plane and capsule/box distances; test exact fit, one-unit too narrow, low ceilings, endpoint caps, turns, bends, and ceilings/obstacles between sampling stations. Include floors exactly at and just above slope and step limits, unsupported gaps and invalid H/R profiles.
- Build tiny explicit triangle fixtures with independently enumerated expected support and swept collisions, including a nominal capsule penetrating a triangle otherwise selected as support, a protrusion outside the allowed contact patch, holes, nonmanifold edges, zero-area triangles, normals pointing the wrong way, near-tangent and quantized-zero samples. Compare accelerated triangle queries against exhaustive scans. A passing test must fail when the production implementation misses an interior segment collision.
- Construct explicit final sample grids around a surface, roof, protected solid and an entrance. Independently enumerate all intersecting cell volumes and mesher contributors; mutate one contributing sample outside the exception and require rejection, including a neighbor chunk whose owned edge creates the triangle. Include an all-solid protected cell changed to all air, with no baseline or final triangles, and a changed density outside a cave's physical radius but inside the hard-subtraction influence. Exercise quantization rounding and saturation at both conversions, filtering across a halo, overhang/multiple vertical crossings, pockets and a post-filter-induced breach. Prove disabled M5 selects the exact old M4 identity and outputs using existing saved fixtures, without replacing old expected hashes.
- Test all X/Y/Z overlap planes and face/edge/corner ownership at negative coordinates and zero; compare complete global samples and mesh borders, vary worker/request order, and assert symmetric portal IDs/positions and region overlap. Deliberately fail one neighbor and confirm no partial portal or stale plan is published. Test cycles and chains of rejected regions against the eventual connectivity/admission rule.
- Inject cancellation at deterministic barriers in each long stage; retain known prior outputs and verify no scratch, partial plan, stale chunk or stale preview escapes. Exercise budget one below/at/above each checked boundary, arithmetic overflow, missing provider, unsupported filter/LOD, two worlds and reentrant teardown. Test with independent hand-calculated certificates and adversarial cases; generation repeated twice is not an independent correctness oracle.

No builds, automation, visual inspection, cooked build, dedicated-server run, cross-host comparison or gameplay movement test has been performed by this document. M4's separately deferred checks remain unverified. M5 acceptance requires the owner's agreed evidence for every planned route and absence of unintended surface breaks.
